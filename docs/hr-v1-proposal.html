Gap: HR work that is done in ERP today is largely unavailable as a first-class experience in our application. V1 closes that gap for the highest-value, data-ready workflows.

2. ERP Data Already Available (Loginentry)

These sources are already connected / referenced in our stack. V1 can be built without inventing new masters.

ERP Object What it contains Approx. size V1 use
empinfo Employee master — EmpCode, Name, Designation, Department, Company, Branch, Date of joining ~18,000 employees Directory, filters, salary base link

Important notes

  • Prefer Attendancemachine for attendance. Older tables attendance / DailyAttendance are often empty.
  • Present = punch with non-null intime on the attendance date.
  • Employee master joins attendance on EmpCode.
  • Dedicated leave / PF / ESI / payslip tables are not yet confirmed in our schema catalog — treat as V2 pending ERP review.

3. Proposed HR Section — Version 1 Scope

A new HR area in the application navigation, covering the workflows below. Everything listed here is feasible from known ERP data (salary formula details to be confirmed with management).

01

Employee Directory

Searchable list by company, department, designation, branch. View EmpCode, name, joining info.

02

Attendance Register

Daily present / absent by company & department. Drill into who punched in and when.

03

Headcount Dashboard

Daily / monthly headcount by designation (generalize today’s stitcher/sewer chat logic).

04

Monthly Attendance Summary

Present days per employee for a selected month — input for salary calculation.

05

Salary Calculation (Attendance-based)

Payable salary from present days × rate / formula (basic, OT, deductions as defined by sir).

06

Daily Reports (existing)

Move / link existing Daily Reports under the HR hub for one place of work.

In scope (V1): Read + calculate + report from Loginentry employee & attendance data.
Out of scope (V1): Leave approvals, PF/ESI filings, payslip PDF generation, recruitment, bank payout matching (bank statement work stays on its own branch).

5. Decisions Needed from Management

To start build on feature/attendance-salary, we need clarity on the points below.

  1. V1 feature set: Confirm which of the six items (Directory, Attendance Register, Headcount, Monthly Summary, Salary Calc, Daily Reports hub) are approved for V1.
  2. Salary formula: How is payable salary calculated today? (e.g. Basic ÷ working days × present days, OT rate, deductions, minimum days, etc.) Share sample Excel / ERP screen if available.
  3. Rate master location: Where is employee basic / wage rate stored — ERP table, Excel, or other system?
  4. Who can access HR: All managers, Payroll role only (IsPayroll), or a new HR role?
  5. Companies / plants in V1: All companies, or pilot one unit first (e.g. stitcher-heavy plants)?
  6. V2 backlog: Confirm leave, PF/ESI, payslips as later phase after ERP table confirmation.

Recommended starting point

Approve Phase A + B immediately (directory + attendance + monthly summary), and run Phase C (salary) as soon as the formula and rate source are shared. This delivers visible HR value quickly while salary logic is finalized with Accounts / HR.

Separate tracks (not mixed)

  • This proposal: HR / attendance / salary → branch feature/attendance-salary
  • Other track: Bank statement categorization → branch feature/bank-statement-categorization

Once decisions are confirmed, implementation can begin on the HR branch without affecting other features.
